# 시나리오 5 — 마크다운 이미지 데이터 유출 · OWASP LLM05 (Improper Output Handling)

## 개념

이전 시나리오들은 "모델이 뭘 하게 만드느냐"(인젝션이 지시를 따르게 함)에 관한 것이었다.
이 시나리오는 그 다음 단계: **모델이 이미 원하는 답을 만들어냈을 때, 그 출력을 화면에
그대로 렌더링하는 것 자체가 위험할 수 있다.**

OWUI 는 답변을 마크다운으로 렌더링한다. `![alt](url)` (이미지) 나 raw `<img src=url>` 는
채팅창에 나타나는 순간 **브라우저가 자동으로 그 URL 에 GET 요청을 보낸다.** 사용자가
아무것도 클릭하지 않아도 된다. 만약 그 URL 의 쿼리스트링에 민감한 값(대화 요약, 시스템
프롬프트 비밀, 카나리아 등)이 들어있다면, 답변이 화면에 뿌려지는 순간 그 값은 공격자
서버로 조용히 전송된다. 사용자 눈에는 기껏해야 깨진 이미지 아이콘 정도로만 보인다.

시나리오 4(웹 인젝션)와 조합하면 공격 체인이 완성된다:
1. 공격자가 통제하는 웹페이지에 숨김 지시문을 심는다 (LLM01)
2. 모델이 그 지시를 따라 민감한 값을 답변에 포함시킨다
3. **그 값을 마크다운 이미지 URL 에 실어 렌더링 시점에 자동 유출한다 (LLM05)**

## 페이로드 (`payloads/`)

유출 채널을 테스트:

| 파일 | 채널 | 사용자 동작 필요? |
|------|------|-------------------|
| `evil_page_md_image.html` | `![](url)` 마크다운 이미지 | ❌ 자동 렌더링 시 GET |
| `evil_page_html_img.html` | raw `<img src=url>` | ❌ 자동 렌더링 시 GET |
| `evil_page_md_link.html` | `[텍스트](url)` 마크다운 링크 | ✅ 클릭 필요 (낮은 위험도지만 여전히 위험) |
| `control_page_citation.html` | 인젝션 없음, 정상 문서 | — (회귀 확인용) |

## 방어: `defense/exfil_guard_s5.py` (outlet 전용)

입력측(request) 방어는 여기서 근본 해결이 안 된다 — 모델이 "유출해도 되는 값"이라고
착각한 게 아니라, 정상적으로 생성한 답변을 렌더링하는 방식 자체가 문제이기 때문이다.
따라서 방어는 **outlet에서 렌더링 직전의 텍스트를 검사**한다:

- **이미지는 도메인 무관 전부 차단** — `![alt](url)`, `<img src=url>` 는 클릭 없이
  자동 요청되므로 애초에 사용자 동의가 성립할 수 없다. `[이미지 차단됨: 외부 URL
  자동 로드 시도]` 로 치환.
- **링크는 화이트리스트** — `allowed_domains` valve 에 없는 도메인의 마크다운 링크는
  하이퍼링크만 제거하고 텍스트는 보존 (정보 손실 최소화). 기본값은 빈 목록 = 전부 차단.

## 한계

- **트레이드오프**: `allowed_domains` 를 비워두면(안전 기본값) 모델이 정당하게 출처를
  인용하는 마크다운 링크도 제거된다. RAG 출처 인용이 필요하면 관리자가 신뢰하는 도메인을
  valve 에 추가해야 한다 — "편의 vs 안전"은 설정으로 넘긴다.
- 이 필터는 **텍스트 마크다운/HTML** 만 본다. 만약 모델이 base64 로 인코딩된 이미지
  data URI(`data:image/...;base64,...`)를 직접 생성한다면 그건 외부로 나가는 요청이
  아니므로(자체 데이터 URI는 네트워크 요청을 만들지 않음) 이 공격 클래스에 해당하지 않는다.
- 근본적으로 이 문제는 "LLM 출력 = 신뢰할 수 있는 UI 렌더링 대상"이라는 가정이 깨질 때
  생긴다 — OWASP LLM05 의 정석적인 예시.
